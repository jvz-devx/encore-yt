# Flatpak

Encore as a Flatpak, built from source with no network. `release.yml` builds a
`.flatpak` bundle for every tag and attaches it to the release; nothing here
has been submitted to Flathub.

- `io.github.jvz_devx.encore-yt.yml`: the manifest.
- `io.github.jvz_devx.encore-yt.metainfo.xml`: the AppStream metadata.
- `cargo-sources.json`: every crate in `Cargo.lock` with its checksum
  (and the one git dependency), generated by `update-sources.sh`. Run that
  script after any change to `Cargo.lock` and commit the result.

The app id is `io.github.jvz_devx.encore-yt`, not `io.github.jvz-devx...`:
Flatpak allows a hyphen only in the last segment. The app reads the id from
`FLATPAK_ID` for its window class, notifications and MPRIS, so they match the
installed desktop file.

## Build and run locally

```sh
flatpak install --user flathub org.freedesktop.Sdk//25.08 \
  org.freedesktop.Sdk.Extension.rust-stable//25.08 \
  org.freedesktop.Sdk.Extension.llvm21//25.08
flatpak-builder --user --install --force-clean build-dir \
  packaging/flatpak/io.github.jvz_devx.encore-yt.yml
flatpak run io.github.jvz_devx.encore-yt
```

The build is a release build (fat LTO), so it takes several minutes. Keep
`build-dir` and `.flatpak-builder` out of the repository; pass `--state-dir`
and a build directory elsewhere if you build in a worktree. To make a bundle:
`flatpak build-bundle ~/.local/share/flatpak/repo encore.flatpak io.github.jvz_devx.encore-yt`
(or use `--repo=repo` with `flatpak-builder`).

## Permissions

Each `finish-args` entry is explained in the manifest. In short: Wayland (X11
only as a fallback), `--device=dri` for the GPU, PulseAudio (PipeWire serves
it), network, the Notifications, tray and KWallet/Secret Service bus names,
and ownership of `org.mpris.MediaPlayer2.encore-yt`.

Inside the sandbox:

- The config and cache folders are `~/.var/app/io.github.jvz_devx.encore-yt/`
  (`XDG_CONFIG_HOME` and `XDG_CACHE_HOME` point there), so the move from the
  old `ytfast` folders does not run and an existing install's sign-in and
  settings are not shared. Sign in again.
- Signing in from a browser reads the browser's cookie database from the real
  `~/.config` and `~/.mozilla`; the app looks there instead of the sandbox's
  config folder when `/.flatpak-info` exists. Only browsers installed as
  packages are covered. Browsers installed as Flatpaks keep their profile in
  their own folder; Firefox and LibreWolf are listed, Chromium-family
  Flatpaks are not.
- `secret-tool` (built from libsecret in the manifest) reads the Chromium
  key from the Secret Service. KWallet is read directly over D-Bus.
- Cookie import uses the file chooser portal, so it needs no permission.
- The tray registers without the `StatusNotifierItem-PID-ID` bus name, which
  a sandbox cannot own.
- The in-app updater does not replace the app (it is read-only); Settings says to use
  `flatpak update`.

## What a Flathub submission needs

Not done; this is the list.

1. A pull request to `github.com/flathub/flathub` (branch `new-pr`) adding the
   manifest as `io.github.jvz_devx.encore-yt.yml`, following Flathub's
   submission guide. On Flathub the `dir` source becomes a `git` source with a
   release tag and commit, and `cargo-sources.json` sits next to the manifest.
   Flathub builds without network, as this manifest already does.
2. App id verification. For `io.github.<user>.<app>` ids Flathub verifies
   through the GitHub account (the login method on the developer page), with
   `jvz_devx` standing for the account `jvz-devx`. The metainfo id must match
   the manifest `app-id` and the desktop file name.
3. A passing `flatpak-builder-lint` for the manifest and the repo
   (`flatpak run --command=flatpak-builder-lint org.flatpak.Builder ...`) and
   `appstreamcli validate` on the metainfo.
4. Screenshots reachable at the URLs in the metainfo (they point at `main`
   on GitHub; Flathub mirrors them). Releases in the metainfo should match the
   tags; add an entry for each release.
5. Reviewer concerns to expect:
   - **Filesystem access.** The read-only browser folders are the broadest
     permission. Reviewers usually refuse broad home access; they may accept
     named folders with a reason, or ask to drop browser cookie reading and
     keep only cookie import through the portal. If so, delete the
     `--filesystem` lines, the Secret Service and KWallet names and the
     `libsecret` module.
   - **Bus names.** `org.kde.kwalletd5/6` and `org.freedesktop.secrets` are
     only needed for the browser sign-in.
   - **Content rating.** The OARS answers are in the metainfo; music with
     explicit lyrics is rated `language-profanity: moderate`.
   - **Unofficial YouTube client.** The name and icon use no YouTube
     branding, and the description says it is unofficial.
   - **Pre-releases.** The tags are alpha builds; Flathub prefers a stable
     release, and the `type="development"` releases are marked as such.
